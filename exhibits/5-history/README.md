# Экспонат V. История, которой не может быть

```
$ git log --oneline --reverse
0000000 Кунсткамера невозможного: фундамент
0000001 Экспонат I. Глобус, который печатает сам себя
0000002 Экспонат II. Простое число, которое говорит
0000003 Экспонат III. Предложение, которое пересчитало себя
0000004 Экспонат IV. Картинка, которая на самом деле архив
0000005 Экспонат V. История, которой не может быть
0000006 Выставочный зал
0000007 Каталог и проверка всех экспонатов
```

Номер коммита в git — это SHA‑1 от его содержимого: дерева файлов, родителя, автора, даты и сообщения. Выбрать его нельзя, можно только угадать. Вероятность, что хеш начнётся с семи заданных цифр, равна 1 к 16⁷ = 268 435 456. Здесь так повезло восемь раз подряд.

Для этого здесь лежит станок. `mint.c` берёт готовый коммит и перебирает невидимый хвост сообщения: 32 символа, каждый из которых пробел или табуляция. Это 4 294 967 296 вариантов. Всё, что стоит до хвоста, хешируется один раз (так называемое промежуточное состояние SHA‑1). Для каждой попытки досчитываются только последние один‑два блока по 64 байта, на четырёх ядрах это примерно 20–26 миллионов попыток в секунду. Нужная комбинация находится в среднем за 268 миллионов попыток, то есть за 10–20 секунд.

```sh
node exhibits/5-history/verify.mjs   # пересчитывает SHA-1 каждого коммита с нуля и показывает невидимые хвосты
git cat-file commit HEAD | cat -A | tail -4   # хвост виден как ^I (табуляции) и пробелы перед $
```

Отправить следующий коммит в ту же историю:

```sh
git add …
node exhibits/5-history/mint.mjs --subject "Заголовок" --trailer "Co-authored-by: Имя <почта>"
```

`mint.mjs` сам соберёт `mint.c` (нужны `cc` и `libcrypto`), возьмёт следующий номер в последовательности, найдёт хвост, запишет объект через `git hash-object` и передвинет ветку.

Чтобы последовательность дошла до `main`, ветку нужно влить без переписывания коммитов. Подходят fast-forward, обычный merge commit или переименование ветки. Squash и rebase на GitHub пересчитывают хеши, и чудо пропадает.
